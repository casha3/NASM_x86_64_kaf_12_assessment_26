# Отладка ассемблерных программ в GDB

Для запуска ассемблерных функций без точки входа `_start` используется `main.c`, который работает с `argc`/`argv`. Это позволяет легко передавать аргументы и выводить результаты, не реализуя собственный ввод-вывод на ассемблере.

> В папке `demo_kr` будет лежать реализация программы для работы со строками с помощью цепочных команд, а также `dumb realization` (без строковых инструкций).

---

## Гайд по отладке функции `f` с использованием `main.c`

### 1. Исходные файлы (описание)

- `func.asm` – реализация функции на ассемблере (содержимое не приводится, но подразумевается).
- `main.c` – программа на C, которая принимает аргумент командной строки, преобразует его в целое число, вызывает `f` и выводит результат.

**Принцип работы:** программа ожидает ровно один аргумент (число). Если аргумент не передан, печатает подсказку. Затем вызывает `f(input)` и выводит аргумент вместе с возвращённым значением.

### 2. Сборка с отладочной информацией

```bash
nasm -f elf64 -g func.asm -o func.o
gcc -g main.c func.o -o test
```

Флаги `-g` включают отладочные символы для GDB.

### 3. Запуск GDB и передача аргумента через командную строку

```bash
gdb ./test
```

Внутри GDB:

```
(gdb) break f
(gdb) run 123
```

Программа запустится с `argv[1] = "123"`, преобразуется в `123`, и остановится на первой инструкции функции `f`. Регистр `edi` будет содержать это значение.

Проверка:

```
(gdb) info registers edi
```

Если аргумент не передан (`run` без параметров), `main` завершится с сообщением об использовании, и точка останова не сработает.

### 4. Принудительное изменение регистра `edi` перед выполнением `f`

Даже если аргумент уже передан, можно подменить значение в `edi`:

```
(gdb) set $edi = -42
```

Теперь функция получит не `123`, а `-42`. Это удобно для проверки разных чисел без перезапуска программы.

### 5. Отладка функции

- **Пошаговое выполнение:** `ni` (next instruction) или `si` (step into).
- **Включение отображения исходного кода:** `layout src` (если есть отладочные символы).
- **Отображение ассемблера:** `layout asm`.
- **Выполнение до возврата из функции:** `finish` – после этого вы остановитесь в `main`, а регистр `eax` покажет возвращённое значение.
- **Прямой вызов функции из GDB:** `call (int) f(100)` – быстрый способ проверить разные входные данные.

### 6. Продолжение и просмотр вывода программы

После отладки функции выполните:

```
(gdb) continue
```

Программа напечатает результат с помощью `printf`. Если вы изменяли `edi`, то `printf` выведет исходный аргумент из командной строки, а результат будет соответствовать подменённому значению (это нормально для отладки).

## Отладка любых программ в GDB с TUI

### 1. Сборка с отладочной информацией

Чтобы видеть исходные строки и метки в GDB, ассемблируйте с флагом `-g`:

```bash
nasm -f elf64 -g program.asm -o program.o
```

Линковка в исполняемый файл:

```bash
ld program.o -o pro
```

### 2. Запуск GDB в многооконном режиме (TUI)

Для разделения экрана на окна исходного кода и ассемблера:

```
layout split
```

Для отображения регистров в отдельном окне:

```
layout regs
```

Переключение между окнами: **`Ctrl-x` затем `o`**.  
Прокрутка активного окна: стрелки.

### 3. Автоматический показ ассемблерной строки при шагах

**Способ 1:** включить отображение следующей инструкции

```
set disassemble-next-line on
```

Теперь после каждого `ni`/`si` будет выводиться строка дизассемблера.

**Способ 2:** показывать текущую инструкцию всегда

```
display/i $pc
```

Эта команда заставляет GDB выводить инструкцию по адресу `$pc` после каждой остановки.

**Способ 3:** ручной вывод при необходимости

```
x/i $pc
```

### 4. Полезные TUI-раскладки

| Команда          | Что отображает                            |
|------------------|-------------------------------------------|
| `layout src`     | Только исходный код (требуется `-g`)      |
| `layout asm`     | Только дизассемблированный код            |
| `layout split`   | Исходный код + дизассемблер               |
| `layout regs`    | Регистры + командная строка               |
| `layout src`     | Исходный код + командная строка           |

### 5. Пример сеанса отладки

```bash
gdb ./pro
```

```
(gdb) set disassemble-next-line on
(gdb) display/i $pc
(gdb) break _start
(gdb) run
(gdb) ni
```

При каждом нажатии `ni` вы будете видеть выполняемую инструкцию и текущее состояние программы.

> **Совет:** чтобы настройки сохранялись, добавьте `set disassemble-next-line on` и `display/i $pc` в файл `~/.gdbinit`.

### 6. Примечание о символах табуляции, пробела и перевода строки

При сравнении байтов в NASM используйте числа или обратные кавычки для управляющих символов. Например, для табуляции – число 9, для пробела – 32, для перевода строки (LF) – 10. Альтернативно можно использовать экранированные символы в обратных кавычках: `` `\t` ``, `` `\n` ``.
