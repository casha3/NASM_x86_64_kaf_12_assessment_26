## Основные ошибки в исходном коде

| Строка / фрагмент | Ошибка | Исправление |
|-------------------|--------|-------------|
| `%define SYS_WRITE` | Не задано значение | `%define SYS_WRITE 1` |
| `mov rsi , [buf2]` | Загружается содержимое по адресу `buf2`, а не сам адрес | `mov rsi, buf2` |
| `mov rdx , rbx` | Выводится столько же байт, сколько прочитано, а не реальная длина `buf2` | `mov rdx, r12` |
| `mov al , byte [buf + rcx]` | Метка `buf` не существует, должно быть `buf1` | `mov al, byte [buf1 + rcx]` |
| `je .keep_skip` без сравнения | Инструкция `je` выполняет переход, если флаг ZF=1, но сравнение не проведено | Добавить перед `je` нужное `cmp` |
| Использование `'\t'` или `'\n'` | В одинарных кавычках escape-последовательности не работают, NASM выдаст предупреждение или ошибку | Заменить на числа (`9`, `10`) или обратные кавычки (`` `\t` ``) |

## Исправленный код с подробными комментариями

Ниже — готовая заготовка для программы, которая читает строку, обрабатывает её (пример логики: заменить первое слово на `abc`, а остальные пробелы/табы сохранить) и выводит результат. Все управляющие символы записаны **корректно**.

```nasm
bits 64

; --- Определение констант ---
%define STDIN      0
%define STDOUT     1
%define SYS_READ   0
%define SYS_WRITE  1      ; обязательно значение!
%define SYS_EXIT   60

; Управляющие символы для сравнения
%define TAB        9
%define LF         10
%define CR         13
%define SPC        32

; --- Секция неинициализированных данных ---
section .bss
    buf1 resb 82          ; входной буфер
    buf2 resb 82          ; выходной буфер

; --- Секция кода ---
section .text
    global _start

_start:
    ; ----- Чтение строки из stdin -----
    mov rax, SYS_READ
    mov rdi, STDIN
    mov rsi, buf1         ; передаём АДРЕС буфера, а не [buf1]
    mov rdx, 81
    syscall
    ; rax = количество прочитанных байт (включая \n)
    mov rbx, rax

    xor rcx, rcx          ; индекс по buf1
    xor r12, r12          ; индекс по buf2

    ; ===== Основной цикл обработки =====
.loop:
    cmp rcx, rbx
    jge .loop_done

    mov al, byte [buf1 + rcx]   ; загружаем очередной символ

    ; --- Проверка на управляющие символы (пробел, табуляция, LF) ---
    ; Используем ЧИСЛА (надёжно) или обратные кавычки для escape
    cmp al, SPC          ; пробел
    je .keep_write
    cmp al, TAB          ; табуляция (9)
    je .keep_write
    cmp al, LF           ; конец строки (10)
    je .keep_write

    ; Здесь можно вставить дополнительную логику.
    ; Например, если символ не пробельный – сохраняем его.
    ; В данной заготовке просто записываем всё подряд.
    jmp .keep_write

.keep_write:
    mov byte [buf2 + r12], al
    inc r12
    ; inc rcx – будет выполнено в .keep_skip (или отдельно)
    ; Для упрощения перейдём к общему увеличению rcx
    jmp .keep_skip

.keep_skip:
    inc rcx
    jmp .loop

.loop_done:
    ; ----- Завершаем выходную строку символом LF -----
    mov byte [buf2 + r12], LF   ; 10
    inc r12

    ; ----- Вывод обработанной строки -----
    mov rax, SYS_WRITE
    mov rdi, STDOUT
    mov rsi, buf2               ; адрес
    mov rdx, r12                ; реальная длина (подсчитана в r12)
    syscall

    ; ----- Корректный выход -----
    mov rax, SYS_EXIT
    xor rdi, rdi
    syscall
```

**Сборка и запуск:**
```bash
nasm -f elf64 program.asm -o program.o
ld program.o -o program
./program
```

> **Примечание по логике:** в данном примере программа просто копирует все символы.  
> Чтобы реализовать конкретный алгоритм (например, замена первого слова на "abc"), вставьте дополнительные проверки и переходы в местах, обозначенных комментарием «здесь можно вставить дополнительную логику».

## Правила работы с символами в NASM

### 1. Печатные символы (буквы, цифры, пробел)
Смело используйте **одинарные кавычки**.
```nasm
cmp al, ' '      ; пробел
cmp al, 'a'      ; строчная a
cmp al, 'Z'
cmp al, '0'
```

### 2. Управляющие символы (табуляция, LF, CR и т.п.)
**Ни в коем случае** не применяйте одинарные кавычки с escape‑последовательностями (`'\t'`, `'\n'`) – это вызовет ошибки.

Два правильных варианта:

#### a) Числовой код (самый надёжный)
```nasm
cmp al, 9        ; табуляция
cmp al, 10       ; перевод строки (LF)
cmp al, 13       ; возврат каретки (CR)
cmp al, 32       ; пробел (тоже работает)
```

#### b) Обратные кавычки (backticks)
```nasm
cmp al, `\t`     ; табуляция
cmp al, `\n`     ; LF
cmp al, `\r`     ; CR
cmp al, `\0`     ; нулевой символ
```

### 3. Рекомендация
Заведите в начале файла константы через `%define` или `equ`, чтобы код был читаемым:
```nasm
%define TAB 9
%define LF  10
%define CR  13
%define SPC 32
```
И используйте их:
```nasm
cmp al, TAB
je .found_tab
cmp al, LF
je .end_of_line
```

## Краткий справочник: коды и примеры

| Название | Код (dec) | Код (hex) | Как записать в NASM (правильно) |
|----------|-----------|-----------|---------------------------------|
| Табуляция | 9 | 0x09 | `9`, `` `\t` `` |
| Перевод строки (LF) | 10 | 0x0A | `10`, `` `\n` `` |
| Возврат каретки (CR) | 13 | 0x0D | `13`, `` `\r` `` |
| Пробел | 32 | 0x20 | `' '`, `32` |
| Нулевой символ | 0 | 0x00 | `0`, `` `\0` `` |
| Звонок (BEL) | 7 | 0x07 | `7`, `` `\a` `` |
| Backspace | 8 | 0x08 | `8`, `` `\b` `` |
| Escape (ESC) | 27 | 0x1B | `27`, `` `\e` `` |

**Пример проверки на пробельные символы (универсальная):**
```nasm
    cmp al, 32      ; пробел
    je .whitespace
    cmp al, 9       ; табуляция
    je .whitespace
    cmp al, 10      ; LF
    je .whitespace
    cmp al, 13      ; CR
    je .whitespace
    ; ... не пробел
